# 공개 배포 저장소 사용 방법

미니 시리즈의 공개 다운로드·자동 업데이트는 `Esper80/mini-app-releases`를 공통으로 사용합니다. 각 앱의 본체 소스·개발·검증은 기존 비공개 저장소에서 관리합니다. 과거 비공개 릴리스는 보존하고 새 EXE는 이 저장소의 GitHub Releases 자산으로 게시합니다. EXE를 Git에 커밋하지 않습니다.

## 앱과 버전

`releases/catalog.json`에 앱별 버전·고정 EXE 이름·x64 아키텍처·태그·SHA-256·크기를 기록합니다. 카탈로그는 서명된 활성 목록을 대신하지 않습니다.

- mini-audio → MiniAudio.exe
- mini-resource-monitor → MiniMonitor.exe
- mini-capture → MiniCapture.exe
- mini-mp3-maker → MiniMP3Maker.exe
- mini-tv-link → MiniTVLink.exe (PC 전용)

공개 태그는 `앱-ID/v버전`입니다. 태그는 이 공개 저장소의 배포 기록 커밋을 가리키며 비공개 소스 커밋과 별개입니다. 버전은 숫자 2~4부분으로 비교합니다. Capture 표시 버전 `1.2`와 내부 Cargo `1.2.0`을 구분합니다. 동일·이전 버전은 설치하지 않습니다. 공동 `releases/latest`는 사용하지 않습니다.

## 업데이트 목록과 서명

클라이언트는 익명으로 `https://raw.githubusercontent.com/Esper80/mini-app-releases/main/updates/stable.json`을 읽습니다. 개발자 토큰은 앱에 넣지 않습니다.

외부 JSON은 `payload`, `signature` 두 Base64 문자열입니다. 디코딩한 원래 UTF-8 payload 바이트에 RSA-3072 / SHA-256 / PKCS#1 v1.5 서명을 검증합니다. 공개키는 각 앱의 업데이트 엔진에 고정됩니다. **서명 뒤 JSON payload를 편집하면 안 됩니다.** GitHub 저장 권한과 서명키는 서로 다른 역할입니다. 서명키는 공개 저장소·빌드 ZIP·EXE에 포함하지 않습니다.

payload에는 `schema: 1`, Unix 초 단위 `generated_at`, `expires_at`, 앱 ID별 `apps`가 있습니다. 앱 항목은 `version`, `arch: win-x64`, `filename`, `tag`, 64자리 소문자 `sha256`, 바이트 단위 `size`만 사용합니다. 임의 다운로드 URL을 넣지 않습니다. 엔진은 고정 저장소와 태그·파일명으로 특정 릴리스 URL을 조합합니다. 태그의 `/`는 URL에서 `%2F`로 인코딩합니다.

목록 최대 128 KiB, EXE 최대 320 MiB, 서명 유효기간 최대 90일입니다. 만료 전 같은 검증 자산으로 목록을 다시 서명·게시합니다. 새 릴리스가 없어도 만료일을 관리해야 합니다. 만료·오프라인·HTTP 오류·서명 오류를 최신 버전으로 표시하지 않으며 기존 앱은 계속 실행됩니다. 키 교체는 기존 키로 전달할 전환 버전부터 설계합니다.

## 게시 순서

1. 해당 작업의 승인 범위와 비공개 소스의 실제 커밋을 확인하고 앱별 빌드·검사·고지 게이트를 통과합니다. 소스 → 후보 → 해시 → 공개 자산의 대응은 비공개 배포 기록에 남깁니다.
2. 검증 후보를 임의 재빌드하지 않고 고정 파일명·내부 버전·크기·SHA-256을 기록합니다. 본체 소스·사용자 파일·토큰·개발 미디어를 배포 폴더에서 제외합니다.
3. 카탈로그 커밋을 대상으로 앱별 새 릴리스 **초안**을 만들고 EXE 및 해당 앱의 필수 자료만 올립니다. 이미 게시한 동일 버전 자산은 다른 바이트로 덮어쓰지 않습니다.
4. 초안 자산을 다시 다운로드하여 전체 파일의 크기·해시를 대조합니다. 태그·설명·EXE 내부 버전·자산 구성을 확인합니다.
5. 정식 게시하고 EXE의 실제 익명 다운로드를 검증합니다. 배포한 파일을 후보와 대조합니다.
6. 확인이 끝난 앱만 포함해 **전체 앱 목록**을 로컬에서 서명하고 엔진의 `verify --manifest <file> --app <id>`로 검증합니다. 다른 앱 항목을 보존합니다. 활성 목록 갱신은 EXE 검증보다 뒤에 합니다.
7. `updates/stable.json`과 운영 기록을 게시하고 실제 클라이언트의 조회·다운로드·캐시 재사용을 확인합니다. README와 비공개 앱의 배포 기록을 갱신합니다.

기존 비공개 저장소의 릴리스 workflow가 이 공개 저장소에 자산을 쓰려면 별도 최소 권한 자격 증명이 필요합니다. 기본 `GITHUB_TOKEN`은 다른 저장소에 쓸 수 없습니다. 자동 게시 환경을 설정하지 않은 경우 승인된 운영자가 수동 GitHub CLI/API 경로로 같은 검증 순서를 수행합니다. 토큰을 커밋하거나 클라이언트에 내장하지 않습니다.

## 클라이언트 동작과 제한

조회·다운로드는 UI 밖에서 실행합니다. 연결 8초·목록 12초·EXE 180초 제한과 상위 호출 제한을 사용하고 앱 종료 시 요청·네트워크 자식을 취소합니다. 동일 앱의 확인/설치가 겹치지 않으며 EXE 캐시는 프로세스 간 잠금도 사용합니다. 다운로드 완료 후 3,600초 미만의 같은 앱·버전·태그·크기·해시 캐시만 다시 검증해 재사용합니다. 목록 조회 자체와 EXE 다운로드 횟수는 별개입니다.

서명·기간·앱·버전·x64 PE·크기·해시·실제 FileVersion/ProductVersion을 검사하고 원본 폴더에 새 EXE를 준비한 다음 정상 종료를 요청합니다. 같은 경로를 교체하므로 설정·인증·결과물은 보존합니다. 부모 종료를 60초 기다리며 강제로 종료하지 않습니다. 재시작 확인 30초 실패 시 이전 EXE로 복구하고 실패 버전 자동 재설치 루프를 막습니다. 관리자 권한을 자동 요청하지 않습니다.

- Audio: 녹음·녹음 일시정지·마무리 중 설치 불가. 재생 중 설치 가능. LGPL 라이브러리 교체 자료·본체 이용 조건을 함께 제공합니다.
- Monitor: 설정 메뉴 안에서 확인/설치. 기존 측정·자동 실행·설정 경로를 유지합니다.
- Capture: 미저장 캡처는 설치 차단 조건이 아닙니다. 릴리스 첨부는 EXE 정확히 하나, 원문 고지는 EXE 내장입니다.
- MP3 Maker: 변환 작업 중 확인·다운로드·설치 불가. 완료 기록은 차단 조건이 아닙니다. 고정된 구성요소의 정확한 원본 소스·빌드 레시피·고지를 제공합니다.
- TV Link: PC 업데이트와 기기 작업/펌웨어는 별개입니다. 기기 작업 중 설치를 제한하며 PC 목록으로 `.bin`을 선택하거나 기기를 자동 플래시하지 않습니다.

## 회수와 복구

문제 자산은 우선 해당 앱의 목록 항목을 제외하거나 이전 검증 항목으로 바꾸고 **다시 서명**하여 추가 설치를 막습니다. 다른 앱 항목은 유지합니다. 목록 회수는 이미 설치된 앱을 자동 다운그레이드하지 않습니다. 수동 복구 안내 또는 새 수정 버전을 게시합니다. 태그 강제 이동·자산 덮어쓰기로 기존 버전을 조용히 바꾸지 않습니다.

처음 지원하는 버전은 한 번 수동으로 다운로드합니다. 기존 바로가기·자동 실행이 버전 포함 이름을 가리키면 새 고정 경로로 전환합니다. 소스 저장소의 비공개 설정은 유지합니다.
